# Product

## Register

product

## Users

Kieran and other children use the app with a parent nearby, usually on a phone, tablet, or family computer. New users should be able to describe an idea and start creating immediately. The parent manages the shared access code and cost, but routine creation should not feel like account or project management.

## Product Purpose

Kieran's Imagination turns a child's prompt or photo into printable coloring art and trading cards. Success is a fast, joyful create-preview-edit loop that keeps work safe automatically. Persistence, jobs, revisions, and model routing exist to make the simple experience reliable; they are not primary navigation concepts.

## Brand Personality

Playful, encouraging, and direct. The product should feel imaginative without becoming noisy, childish in a patronizing way, or technically complicated.

## Anti-references

- Workspace and project-management products that require naming or organizing a container before doing the primary task.
- Dashboard-first home screens, empty-state administration, and visible backend terminology such as Worlds, Jobs, revisions, models, or credits.
- Mandatory login before a new visitor can try the core creation flow.
- Expensive-model defaults when a fast, inexpensive model can produce a useful result.

## Design Principles

1. Creation before organization: the first screen starts making something.
2. Zero setup: create an implicit collection automatically and ask for names only when the user chooses to organize.
3. Persistence is invisible: save every useful result without interrupting the flow.
4. Reveal depth progressively: history, cards, print quality, and advanced edits stay nearby but secondary.
5. Optimize for the child: use familiar words, obvious actions, short waits, and forgiving recovery.
6. Preserve the classic visual identity: the large illustrated logo, oversized comic lettering, glowing prompt card, colorful gradient actions, and spacious single-purpose layout are core product character, not decoration to flatten into a conventional app shell.

## Visual Source of Truth

The pre-platform UI at commit `015818d` and `assets/kieran-app-home.png` define the intended visual direction. New backend capabilities should be fitted into that experience. Do not replace it with a dashboard, compact navigation header, generic card grid, or productivity-app layout.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Use readable contrast, large touch targets, keyboard-visible focus, semantic labels, and status text that does not rely on color. Respect reduced-motion preferences and avoid decorative motion that delays interaction. Copy should be understandable to a young reader while remaining clear to the parent.
